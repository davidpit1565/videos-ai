# Studio — הפעלה

מערכת הניהול של הערוץ: פרקים, מדדים, צמיחה, מקורות הכנסה וסוכן שקורא את המספרים.
עובדת בדפדפן במק ובטלפון (אפשר להוסיף למסך הבית — היא נפתחת כמו אפליקציה).

## מה עובד בלי שום מפתח

הכל, חוץ מהמשיכה האוטומטית של המספרים. בלי `DATABASE_URL` המערכת שומרת בדפדפן
שממנו עבדת — זה אמיתי ולא נעלם, אבל זה לא מסתנכרן בין המק לטלפון. הכיתוב בפינה
העליונה אומר בדיוק במה אתה נמצא: **נשמר בדפדפן** או **מסד נתונים**.

## הכתובת החיה

הפרויקט ב-Vercel כבר קיים ופרוס: **actually-works-studio** (Root Directory: `studio`).

    https://actually-works-studio.vercel.app

זו הכתובת הראשית, וזו הכתובת שצריך לשמור. הכתובת הארוכה של הענף
(`...-git-claude-universa-610c01-...`) היא **בנייה קפואה מהעבר** — בניות ענף כבויות
ב-`studio/vercel.json`, ולכן היא לא מתעדכנת ולא רואה את משתני הסביבה. אם היא נראית
שונה ממה שמצפים, זו הסיבה. הכתובת הראשית נבנית מחדש בכל מיזוג ל-`main`.
אפשר להוסיף אותה למסך הבית באייפון (Share → Add to Home Screen) והיא נפתחת כמו
אפליקציה, בלי שורת כתובת.

## משתני סביבה

Vercel → Project → Settings → Environment Variables. אף אחד מהם לא נכנס לגיטהאב
ולא לצ'אט.

| שם | בשביל מה | איפה משיגים |
|---|---|---|
| `DATABASE_URL` | סנכרון בין המק לטלפון | Vercel → Storage → Create Database → Postgres (חינם). ה-URL נוצר לבד |
| `ANTHROPIC_API_KEY` | הסוכן בתוך המערכת | console.anthropic.com → API Keys |
| `BEEHIIV_API_KEY` | מספר הנרשמים | Beehiiv → Settings → API |
| `IG_ACCESS_TOKEN` | צפיות, שמירות, שיתופים לכל פרק | לפי `publish/SETUP.md` — אותו טוקן של הפרסום |
| `IG_USER_ID` | מזהה חשבון האינסטגרם המקצועי | שם, באותו תהליך |

`BEEHIIV_PUBLICATION_ID` כבר בקוד (הוא מזהה ציבורי, לא סוד). אם תפתח פרסום אחר,
אפשר לדרוס אותו במשתנה סביבה באותו שם.

חיבור שחסר לו מפתח לא שובר כלום — הוא מציג בלוח בדיוק איזה משתנה חסר.

### לבדוק חיבור בלי לנחש

    https://actually-works-studio.vercel.app/api/connections

הכתובת הזאת פתוחה (בלי קוד) ומחזירה שורה אחת של JSON: לכל משתנה — אם הוא **קיים**
בפריסה הזאת, באורך כמה תווים, בשתי האותיות הראשונות, והאם נדבק לו רווח או שורה חדשה
בהעתקה. **את הערך עצמו היא לא מחזירה, אף פעם.** מתחת לזה יש את התשובה של אינסטגרם
ושל Beehiiv עצמם — זה מה שקובע.

שני דברים שהיא פותרת, ושניהם עלו לנו יום כל אחד:

- **`env`** אומר איזו פריסה ענתה (`production` או `preview`). משתנה שנשמר ל-Production
  בלבד פשוט חסר בפריסת preview — וזה נראה בדיוק כמו "לא שמרתי אותו".
- **`edgeSpace: true`** אומר שהערך תקין אבל נדבקה לו שורה חדשה בהעתקה. זה מספיק כדי
  שהשירות ידחה אותו.

אחרי שינוי של משתנה סביבה ב-Vercel צריך **Deploy** חדש כדי שהוא ייכנס לתוקף. פריסה
קיימת לא קוראת את הערך החדש.

## איך זה מתחבר לפרק

אינסטגרם לא מספר לאף אחד "הפוסט הזה הוא פרק 3", ולכן:

1. אחרי שפרק מתפרסם, לוחצים **משיכת מספרים מאינסטגרם** בעמוד הפרקים.
2. הפוסט מופיע למטה תחת "קישור לפוסטים באינסטגרם" — בוחרים לאיזה פרק הוא שייך.
3. מכאן כל משיכה מעדכנת את הפרק הזה לבד.

## מה נמדד ולמה

- **שמירות לצפייה** — המדד היחיד שמבדיל בין הוק שעבד לבין תוכן שעבד. אדם ששומר
  סרטון התכוון לחזור ולהשתמש בו.
- **מדידה** — כל האינטראקציות חלקי צפיות. זה מה שקובע עד כמה הסרטון ימשיך להיחשף.
- **נרשמים לפרק** — נכנס ביד, כי אין API שמייחס נרשם לסרטון. מספר מוזן ביד עדיף
  על מספר מומצא, ועל אין מספר בכלל.

הסוכן רואה רק את מה שיש במערכת. אם חסר מספר הוא יגיד איזה — הוא לא ינחש.
